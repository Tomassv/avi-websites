# cura.aero

Marketing site and internal documents for Cura, the claims resolution platform for airlines.
Next.js 16 (App Router, TypeScript), deployed on Vercel from this folder.

## Commands

```sh
npm install
npm run dev        # http://localhost:3000; drafts are visible (see "Drafts" below)
npm run build      # production build (type-checks content too)
npm start          # serve the production build
npm test           # unit tests (node --test, no extra dependencies)
npm run typecheck
```

Node 22.18 or newer.

## Environment

The internal pages sit behind HTTP basic auth (`proxy.ts`). Set both variables, locally in
`.env.local` (see `.env.example`) and in Vercel for Production and Preview:

| Variable | |
|---|---|
| `INTERNAL_USER` | basic-auth user name |
| `INTERNAL_PASSWORD` | basic-auth password |

If either is missing, every internal page returns 401. Public pages are unaffected.

## Where things live

| Path | What |
|---|---|
| `content/` | **All copy.** One JSON file per page in `content/pages/`, shared copy in `content/site.json` and `content/shared/`, articles in `content/articles/`, landing pages in `content/landing/` (schema: `content/landing.schema.json`). |
| `app/(site)/` | Public pages: `/`, `/book-demo`, `/evidence-automation`, `/news`, landing pages at `/<slug>` (`[slug]/`), and the draft-only `/landing-catalog`. Site CSS, fonts and Google Analytics. |
| `app/(docs)/` | Internal documents (basic auth): `/evidence-package`, `/workflow`, `/update`, `/value-props`, `/aha`, `/non-connected-value`. |
| `app/(deck)/` | Slide decks (basic auth): `/aireuropa`. |
| `templates/` | Page templates: Marketing, Doc, Deck, Article, News list. |
| `components/` | Layout components. They render content; they never contain copy. |
| `styles/` | `site.css` (the original stylesheet), per-page CSS in `styles/pages/`, `deck.css`, `news.css`. |
| `lib/` | Content types and loaders, the markup parser, URL validators, basic auth, article loader. |
| `public/` | Images in `public/images/` (landing-page images in `public/images/landing/<slug>/`), plus `robots.txt`. The sitemap is generated by `app/sitemap.ts`. |

Old `.html` URLs (and `/assets/*`, `/values/*`) redirect permanently to the new ones; see
`next.config.ts`.

## Editing content

Content files are treated as untrusted input. Text is always escaped; a few inline tags are allowed:

- `<br>`, `<strong>`, `<b>`, `<em>`
- `<span class='…'>` with the classes `orange`, `hi`, `hi-orange`, `hi-white`, `text-bold`, `wf-lead` or `ev-quiet`

Any other tag or attribute is stripped (see `lib/rich.ts`), and `npm test` fails if a content file
uses one. Links may only be site paths (`/…`), anchors (`#…`), `https://` or `mailto:`. Images must
be files under `/images/`. Each content file has a TypeScript type in `lib/content-types.ts`, so a
file with a missing or misspelled field fails the build.

## Adding an article

Create `content/articles/<slug>.md`. The slug is the URL, `/news/<slug>`, and uses lowercase words
joined by hyphens:

```md
---
title: "Article title"
description: "One or two sentences for the list and search results."
date: 2026-10-01
author: AviLabs        # optional
image: /images/news/hero.jpg   # optional, under /images/
draft: true            # true: never on the live site (see "Drafts")
---

Plain Markdown. Raw HTML is ignored.
```

Set `draft: false` to publish. `/news` is not linked from the site yet, and both news routes are
`noindex` and left out of `sitemap.xml` until the section launches.

## Drafts

Draft articles, draft landing pages and `/landing-catalog` are hidden **only on the live site**
(`VERCEL_ENV=production`). They are shown by `npm run dev`, by a local `npm run build`, and on
Vercel preview deployments, with a small "Draft, not live" badge in the corner and
`noindex, nofollow`. The rule is `showDrafts()` in `lib/env.ts`. The sitemap never lists drafts.

## Landing pages

A landing page is one JSON file, `content/landing/<slug>.json`, served at `/<slug>`. It is built
from an ordered list of sections chosen from a fixed catalog, and uses the site header, footer,
fonts, styles and Google Analytics. There's no code to write.

To see every section with sample content, run `npm run dev` and open
[/landing-catalog](http://localhost:3000/landing-catalog). A full example is
`content/landing/claims-automation.json`, a draft at `/claims-automation`.

### Adding a page

1. Pick a slug: lowercase words joined by hyphens, for example `fleet-operations`. It becomes
   the URL.
2. Put the page's images in `public/images/landing/<slug>/`. Every image a page uses must be in
   its own folder, including the og image and the cta-band photos.
3. Create `content/landing/<slug>.json` with `"draft": true`, then check it with `npm run dev`.
4. Set `"draft": false` to publish. The page is added to `sitemap.xml` unless `seo.noindex` is
   true.

```jsonc
{
  "$schema": "../landing.schema.json",          // optional: editor autocomplete and checking
  "draft": true,
  "seo": {
    "title": "Fleet operations — Cura",          // 10–70 characters
    "description": "…",                          // 50–160 characters
    "ogImage": { "src": "/images/landing/fleet-operations/og.jpg", "alt": "…" },
    "noindex": false                             // optional: publish, but keep out of search
  },
  "header": {
    "nav": [{ "label": "How it works", "href": "#how-it-works" }],   // up to 6 links, may be []
    "cta": { "label": "Book a Demo", "href": "/book-demo" }
  },
  "sections": [
    { "type": "hero", "title": "…" }
  ]
}
```

The canonical URL, Open Graph and Twitter tags, and WebPage structured data are generated from
`seo`.

### Rules

Every file is checked against `content/landing.schema.json` when the site is built, and by
`npm test`. Drafts are checked too. A file that breaks a rule fails the build, and the error names
the file and the field:

```
content/landing/fleet-operations.json: sections[3] (cards): unknown field "layout"
content/landing/fleet-operations.json: seo.title: must be at most 70 characters (is 80)
```

- **Strict shape.** Unknown fields, missing required fields and unknown section types are errors.
  Text fields have maximum lengths, and markup counts toward them.
- **Text.** Fields marked *rich* may use the inline tags listed in "Editing content" above.
  Other markup is an error, not stripped. Write a literal `<` or `>` as `&lt;` or `&gt;`. Fields
  marked *text* take no markup at all.
- **Links.** A link is `{ "label", "href", "newTab"? }`. `href` must be a site path (`/book-demo`),
  an anchor on the page (`#faq`), an `https://` URL or a `mailto:` address.
- **Images.** An image is `{ "src", "alt" }`. `src` must be a jpg, png, webp, avif or svg file in
  `/images/landing/<slug>/`, and the file must exist. Use `"alt": ""` for decorative images.
- **Anchors.** Any section can have an `id` (lowercase letters, digits and hyphens), so header
  links like `#faq` can point at it. Ids must be unique on the page.
- **Slugs** can't take a URL that is already in use: a route in `app/`, a redirect in
  `lib/redirects.ts`, or a name in `public/`. For example, `book-demo.json` fails with
  `slug "book-demo" collides with the route app/(site)/book-demo`.
- **One of each.** A page can have at most one `cta-band` and one `book-demo`.

### Changing the catalog

A new section type needs changes in four places:
- a `section-<type>` definition in `content/landing.schema.json`, with a `$ref` in `section.oneOf`;
- a type in `lib/content-types.ts`;
- a component and a `case` in `components/landing/Sections.tsx`, with any new CSS in
  `styles/landing.css`;
- a sample in `content/landing-catalog.json`.

`npm test` fails if the catalog or the renderer is missing a type.

## Adding a deck or an internal page

- **Deck:** add `content/pages/<name>.json` shaped like `aireuropa.json` (typed slides, checked at
  build time) and a route in `app/(deck)/<name>/page.tsx` that renders `DeckTemplate`.
- **Internal document:** add a route under `app/(docs)/` using `DocTemplate`.
- **Either way, add the route to the `matcher` in `proxy.ts`.** `npm test` fails if an internal
  route is missing from it.

## Tracking and embeds

- Google Analytics (`gaId` in `content/site.json`) loads on the public pages only, and only on the
  `cura.aero` / `www.cura.aero` hosts.
- `/book-demo` (and the landing `book-demo` section) embeds the HubSpot meetings calendar; its URL is in `content/pages/book-demo.json`.
- Links between pages are plain `<a>` tags (full page loads). This keeps each page's CSS separate
  and GA page views working as before, so don't switch them to `next/link` without handling both.
